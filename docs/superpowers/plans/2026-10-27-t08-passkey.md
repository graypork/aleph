# T08 Passkey Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add passwordless passkey protection to a new private area on the existing public introduction page while satisfying T08-C01~C53 evidence requirements.

**Architecture:** Keep the existing Vite public page. Add a small passkey UI module plus Vercel Functions backed by existing Upstash Redis. Use SimpleWebAuthn for standards-compliant WebAuthn generation/verification and server-side session ownership for private data.

**Tech Stack:** Vite, vanilla JS, Vercel Functions, Upstash Redis REST, `@simplewebauthn/browser`, `@simplewebauthn/server`, Node test runner.

**Spec:** `docs/superpowers/specs/2026-10-27-t08-passkey.md`

## Global Constraints
- No password UI or password fallback.
- Existing public introduction content remains unauthenticated.
- Private note contents never appear in unauthenticated HTML/source.
- All private data is synthetic.
- Challenge TTL is 5 minutes and challenges are single-use.
- Session cookie is HttpOnly/Secure/SameSite=Lax and server-side sessions expire after 8 hours.

## Review Focus
- Replayed registration/authentication challenges must fail after first consumption.
- Client-supplied account IDs must never authorize another account's private notes.
- A second passkey can be added only by an authenticated owner once the account is initialized.
- Deleting one of two passkeys must not invalidate the remaining passkey.
- Cancelled browser WebAuthn prompts must not persist a credential.
