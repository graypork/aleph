# T07 PlanDoSee Auth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the final T06 PlanDoSee diary with Supabase Auth, per-user ownership/RLS, authenticated evidence, account controls, and the five-day T07 experiment without fabricating future usage records.

**Architecture:** Keep the existing Vercel API and minimal PLAN → DO → SEE frontend. The browser signs in with Supabase Auth using a publishable key, sends the access token in `Authorization`, each API validates the current user and forwards the user JWT to PostgREST, and Postgres RLS performs row-level ownership enforcement. Add an additive T07 migration so the currently deployed T06 server-secret path remains functional while the branch is being built.

**Tech Stack:** Vite, vanilla JS/CSS, Vercel Functions, Supabase Auth/Postgres/PostgREST, `@supabase/supabase-js` exact pinned 2.117.3, Node built-in test runner.

**Spec:** `docs/superpowers/specs/2026-10-16-pds-auth-design.md`
